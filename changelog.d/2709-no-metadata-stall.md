### Fixed
- **A magnet that never gets its metadata is now failed instead of sitting in the queue for ever** (#2709): a torrent your client accepted but never resolved has no file list, no size and no progress, and none of the clients call that an error, so it stayed at "downloading" indefinitely. One reporter's had been there 34 days. Once such a torrent is older than the stall timeout (Settings, 2 hours by default) Bindery now treats it as stalled: it is removed from the client, the queue row fails with "the download client never resolved this magnet's metadata", the release is blocklisted and a fresh search runs. Nothing is judged before the timeout, because a healthy magnet looks exactly the same while it resolves. Covers Transmission, qBittorrent, Deluge and rTorrent. Thanks to ccarpinteri for the report and the diagnosis.
